## 4. 보류 — 권고 사항 (7건)

수정하지 않은 이유와 함께 남긴다. 착수 시 STATUS.md "진행 중"으로 승격.

1. **투자 가설(macro) 검증이 토픽 무관 대조** (`thesis_tracker.py`) — macro 가설은 최근 7일 *모든* 매크로 시그널과 대조되므로, 무관한 부정 뉴스 3건만으로 가설이 자동 invalidated될 수 있다. 다만 "macro→MacroSignal 전체"는 DEVLOG에 기록된 설계 의도라 토픽 연관성 필터는 설계 변경(가설-토픽 매칭 규칙 정의)이 선행돼야 한다.
2. **레버리지 계산기 수식 중복** (`leverage-calc/page.tsx`) — KRW 포맷터·월환산·이자 공식이 백엔드 `leverage_analysis.py` 및 패널 컴포넌트와 3중 중복, 파일 내부에서도 트레이드/수동 모드 간 수수료·요약 블록 복붙. 동작은 정상이라 UI 리팩터링은 별도 작업으로.
3. **분석 파이프라인 N+1·반복 쿼리** — `thesis_tracker`(가설별 동일 시그널 윈도 재조회), `sector_rotation`(섹터당 2쿼리×10), `volatility_forecast`(7일/14일 윈도 이중 조회 + pykrx 무캐시 라이브 스크랩), `ai_analyzer`(문서마다 provider 적중률 재계산 ~9쿼리). 로컬 SQLite 소규모 데이터라 체감 영향은 작지만 데이터가 쌓이면 배치가 느려진다.
4. **브로커 예수금 함수 복붙** (`broker_deposit_sync.py`) — KIS/키움용 거의 동일 함수 2벌. 세 번째 브로커 추가 전에 공통화 권장.
5. **하드코딩 리스트** — `KNOWN_PATTERNS`(9개)·`ROTATION_SECTORS`(10개)에 없는 토픽/섹터는 패턴·로테이션 감지에서 영구히 제외된다. 실제 시그널 데이터에서 후보를 도출하는 방식으로 일반화 여지.
6. **시작 캐치업 동시성** (`main.py`) — WAL+busy_timeout으로 완화했으나, 근본적으로는 캐치업 완료 후 스케줄러를 시작하는 순서 조정이 더 안전하다.
7. **market_calendar 공휴일 미지원** — 이번엔 스냅샷 생략 가드로 증상을 막았고, KRX 휴장일 캘린더 반영은 별도 작업.

## 5. 검증 방법

- 후보 발굴: diff 전체 + 신규 untracked 모듈을 8개 관점으로 병렬 탐색.
- 건별 검증: 코드 라인 근거를 인용해 CONFIRMED/PLAUSIBLE/REFUTED 판정 — REFUTED 0건.
- 수정 후: 백엔드 전 모듈 임포트, 노후 스냅샷·공부하기 커리큘럼 API 실호출, 프론트 `tsc --noEmit` 통과 확인.
- 컨벤션 검사(Next.js deprecated API 등)는 위반 0건.
