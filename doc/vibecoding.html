⚙️ 표준 워크플로 — 기능 하나가 지나는 6단계

2026-05-31 ~ 07-12 사이 모든 기능이 이 경로를 따랐습니다. 단계를 건너뛴 곳에서 사고가 났습니다.

탐색 — 기존 패턴부터 찾는다

새 코드를 쓰기 전에 같은 일을 하는 기존 인프라(JSON 저장소, AI 호출 래퍼, 카드 컴포넌트, api.ts 패턴)를 먼저 찾아 재사용. 예: 노후생활 기능은 새 테이블 0개.

계획 — 여러 층을 건드리면 구현 전에 합의

백엔드+스케줄러+프론트+문서를 함께 바꾸는 규모면 계획을 세우고 확인받는다. 소규모 수정은 바로 구현.

구현 — 백엔드 → API → 프론트 순서

파일별 컨벤션(라우터 등록, 프리픽스, 스타일)을 그대로 따른다. 도메인 판단·비용이 걸린 결정은 사용자에게.

검증 — 실데이터로, 끝까지

tsc 타입체크 → 백엔드 모듈 임포트 → API 실호출 → 브라우저 렌더링 확인. 외부 데이터(종목코드 등)는 등록 전 사전 검증(pykrx 조회로 문서의 코드 오류를 실제로 잡았음).

기록 — 아래 체크리스트대로

버전 뱃지·변경로그·DEVLOG·STATUS·문서 인덱스. 기록 규칙이 세션 간 컨텍스트 복원의 재료가 된다.

발행 — 원커맨드

./publish-docs.sh 한 번으로 GitHub Pages + 앱 내 참고자료 동기화 + 사설 IP 검사까지.

✅ 기능 완료 체크리스트

"끝났다"고 말하기 전에 전부 체크. 하나라도 빠지면 다음 세션의 복원력이 깎입니다.

  • 실데이터 검증 통과 — API 실호출 + 브라우저 확인 + tsc --noEmit
  • frontend/lib/version.ts의 APP_VERSION을 날짜+시간으로 갱신
  • frontend/lib/changelog.ts 맨 앞에 사용자 언어로 항목 추가
  • doc/DEVLOG.md에 이력 append (과거 항목 수정 금지 · API 키 값 기록 금지)
  • doc/STATUS.md 갱신 — 완료 행 추가/진행 중 행 이동, 기준일 갱신
  • 새 문서가 생겼으면 doc/index.html + doc/README.md에 날짜와 함께 등록
  • ./publish-docs.sh 실행 (문서가 바뀐 경우)
  • 새 규칙·주의사항이 생겼으면 AI 메모리에 저장 (다음 세션 대비)

📏 규칙 카드 — 흩어진 문서 속 규칙을 한 곳에

각 카드의 출처 문서가 원본입니다. 규칙이 바뀌면 원본을 고치고 이 페이지를 갱신하세요.

버전 뱃지 · 변경로그

눈에 띄는 기능이 추가될 때마다 APP_VERSION(날짜+시간) 갱신 + 변경로그 항목 추가. 헤더 뱃지 클릭으로 사용자가 직접 확인.

바이브코딩-프로세스 §4
DEVLOG는 append-only

큰 기능·연동마다 항목 추가, 오래된 항목은 고치지 않음(시점 기록물). API 키는 이름·용도·발급처만 — 값은 절대 기록 금지.

DEVLOG 머리말·갱신 규칙
STATUS는 현재 스냅샷만

완료/진행 중/알려진 이슈 3분류 유지. 세부 이력은 git과 DEVLOG가 담당. 큰 기능 완료·착수 시 행을 옮기고 기준일 갱신.

STATUS 갱신 규칙
IDEAS → STATUS 승격

떠오른 아이디어는 한 줄로 IDEAS에 적어 두고, 착수하면 STATUS "진행 중"으로 승격. 대화 중 아이디어 유실 방지.

IDEAS 머리말
문서 형식 — 날짜 필수

모든 문서 첫머리와 인덱스 항목에 작성일/기준일 표기. 점검·조사 리포트는 doc/report/YYYY-MM-DD-주제.md.

doc/README 문서 형식 규칙
실사용 DB 보호

사용자가 대화 도중에도 앱에 실데이터를 입력한다. 테이블 통삭제 금지, 테스트 스크립트는 core 함수의 내부 commit 여부부터 확인.

AI 메모리 (세션 간 상시 규칙)
비용이 걸린 작업은 사용자 결정

AI 재분석·백필·유료 모델 전환처럼 비용이 발생하는 작업은 AI가 임의로 실행하지 않고 반드시 사용자에게 묻는다.

바이브코딩-프로세스 §6-10
전반 점검 리포트

다관점 병렬 점검 → 건별 검증 → 수정 → 날짜 리포트 발행. 보류 항목은 리포트에 권고로 남겨 다음 착수 후보로.

🧨 교훈 — 실제 사고에서 뽑은 원칙 10

전부 이 저장소에서 실제로 발생하고 수정된 사례입니다. 상세 경위는 과정 기록 §6과 점검 리포트에.

조용한 폴백 금지 — 스냅샷이 몰래 전일 데이터로 대체돼 이중 저장 사고. 없으면 없다고 남기고 스킵.
외부 API 기본값 불신 — 파라미터 하나 안 보내서 넥스트레이드 체결 344건 조용히 누락. 신설 파라미터가 생기면 기존 연동 재점검.
프롬프트 JSON 예시는 전체 스키마로 — 생략 표기 하나로 5주간 매크로 Signal 0건.
falsy-zero 구분 — "값이 0"과 "값이 없음"을 truthy로 가르면 실측 0원이 등록값으로 둔갑.
날짜는 로컬(KST)로 조립 — toISOString()은 UTC라 결제일이 하루씩 밀렸다.
파일 이동 = 하드코딩 경로 전수 검색 — 문서 하나 옮기자 학습 레슨 본문 전체 공백 + lru_cache가 빈 결과를 고정.
알림은 엣지 트리거로 — 임계값 유지 중 매 갱신마다 알림 누적(하루 8건). "처음 넘을 때 1회" 플래그 패턴.
실사용 DB 위임을 잊지 말 것 — 대화 도중에도 실데이터가 들어온다. 파괴적 조작 금지.
라이브러리 한계는 앱에서 관대하게 패치 — 업스트림 수정(python-kis v3)을 기다리지 않고 미지 코드를 KRX로 우회 처리.
표본 부족 데이터로 추정하지 않기 — 1건짜리 패턴의 +45%가 포트폴리오 예상 손익을 좌우할 뻔. 최소 표본 필터.
